# 개발 기록 · Food Lab

README에서 줄인 내용을 그대로 옮겨 둔 문서입니다.

## 개발하면서 겪은 문제들

**pip 설치가 cp949 오류로 실패**
`requirements.txt` 첫 줄에 한글 주석을 달았더니, Windows pip이 파일을 cp949로 읽다가 `UnicodeDecodeError`가 났습니다. 주석을 영어로 바꿔서 해결했습니다.

**두 번째 색인에서 `Error loading hnsw index`**
제일 오래 걸린 문제입니다. 1,156건 색인은 성공했는데, 다시 실행하니까 ChromaDB가 색인을 못 열었습니다. 폴더를 열어 보니 벡터 파일(`data_level0.bin` 등 4개)이 아예 없었습니다. 원인은 경로에 한글(`교육생배포용`)이 들어 있어서 ChromaDB의 C++ 부분이 파일을 못 쓴 것이었습니다. 데이터가 100건을 넘어야 이 파일을 만들기 때문에, 20건으로 시험할 때는 문제가 안 보였습니다.

`check_chroma.py`를 만들어서 확인했습니다. 임의 벡터 300개로 한글 경로와 영어 경로에서 각각 쓰고 다시 열어 봤는데, 한글 경로는 파일 0/4로 실패하고 영어 경로는 4/4로 정상이었습니다. 그래서 Windows에서 경로에 한글이 있으면 저장 위치를 사용자 폴더 아래로 자동으로 옮기게 했습니다. 색인 직후 벡터 파일이 실제로 있는지도 확인하게 했습니다. 이 문제 때문에 전체 색인을 한 번 더 해야 했습니다.

**GMS 502 Bad Gateway**
20건 시험 색인 중에 GMS가 한 번 502를 돌려줬습니다. 5xx는 재시도하게 해 둬서 바로 성공했지만, 요청 수가 계획보다 1회 많게 나왔습니다. 재시도 기록은 `index_manifest.json`에 남습니다.

**같은 질문인데 위키를 또 검색함**
LLM이 같은 질문에도 매번 조금 다른 검색어를 만들어서, 이미 수집한 질문인데 새 문서를 또 수집했습니다. 질문별로 프롬프트 1 결과를 저장해 두고 재사용하게 바꿨습니다.

**조건 탐색이 엉뚱한 결과를 냄**
처음에는 후보 20개를 LLM이 보고 조건에 맞는 걸 고르게 했습니다. 그런데 "나트륨 적고 15분 안에 만드는 반찬"을 넣으니 후식이 섞여 나오고, 데이터에 없는 "15분 내 가능"을 지어냈습니다. 지시를 더 엄격하게 바꾸니까 이번에는 0건이 나왔습니다. 원인을 보니 "15분"처럼 데이터에 없는 조건까지 LLM에게 판단시킨 게 문제였습니다. 그래서 조건을 세 종류로 나눴습니다. 수치 조건은 코드로 거르고, 판단 불가 조건은 판단하지 않고 안내만 하고, "맵지 않은" 같은 조건만 걸러진 후보 안에서 LLM이 재료를 보고 고르게 했습니다. 결과 카드의 설명도 원본 수치를 먼저 보여 줍니다.

**답변에 별표가 그대로 보임**
`**5g(1작은술)**이`처럼 한글 조사가 바로 붙으면 마크다운이 굵은 글씨로 인식을 못 해서 `**`가 그대로 보였습니다. 프롬프트에서 굵은 글씨와 제목을 쓰지 말라고 하고, 화면에 보여 줄 때도 한 번 정리하게 했습니다.

**화면이 어디서 뭘 해야 할지 모르겠음**
처음에는 사이드바에서 냉장고 재료를 넣고 레시피를 골라야 질문할 수 있었는데, 직접 써 보니 불편하고 재료 칸도 잘 안 보였습니다. 그래서 바뀐 점은 이렇습니다.
- 첫 화면을 "AI 셰프에게 묻기"로 바꾸고, 레시피를 안 골라도 질문할 수 있게 했습니다.
- 사용 순서를 3단계로 보여 주고, 예시 질문 버튼과 오늘의 추천 메뉴를 넣었습니다.
- 입력칸은 테두리를 넣어서 크게 만들었습니다.
